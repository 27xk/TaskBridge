# 同步监控

将 `prometheus.yml.example` 中的 target 改为后端实例地址，把部署配置的 `METRICS_TOKEN` 放入仅采集器可读的凭据文件。将 `alerts.yml` 挂载到示例 `rule_files` 路径；在 Grafana 导入 `grafana-dashboard.json` 并选择 Prometheus 数据源。无需修改应用页面。

指标覆盖同步请求成功 / 失败、push 结果与冲突数量、pull 变化量、耗时分布，以及客户端上报的队列与未解决冲突。告警默认关注持续 5 分钟的 5% 同步错误率、超过 10 分钟的积压和服务不可用，可按实际基线调整。

客户端上报至少间隔 60 秒，仅在有效会话下执行。快照最多保留 10,000 个工作区，15 分钟过期；标签仅含 `source`，不暴露用户、设备、标题或任务 ID。没有上报的离线设备状态未知，不能将零值理解为所有设备均已同步。最近成功年龄未知时不参与最大值。

HTTP 和客户端快照指标保存在进程内，重启后清零。多进程部署应直接采集各实例；请求次数可以聚合，工作区快照可能在实例间迁移，不能直接相加解释为全站唯一设备总量。面板按实例展示队列，告警逐实例评估；告警不是持久审计记录。
